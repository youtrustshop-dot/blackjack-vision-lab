## Demonstrated causes and bounded changes

At 3.2 seconds of development overlap, dealer Q and its blue hole card form one
merged light surface. The rank reader finds Q, but neither a separate unknown
body nor a localized back. V1's context override can only classify existing
unknown bodies. V2 finds separate bright-rimmed textured blue surfaces in declared
card zones and deduplicates them. Back ranks/suits stay unknown; new back
proposals do not clear unrelated rejected glyphs. Plain blue and rimless patterns
are negative tests. This remains a bounded upright blue-pattern rule.

The missed/duplicated exposure is a real tracker error: after upcard 4 recenters,
another 4 is revealed. Greedy association swaps the physical upcard/hole identity
and creates another ID for the original upcard. V2 globally aligns upright rows
left-to-right, allows missing/new observations and reports near-tied alternatives
as uncertainty. The default tracker retains legacy behavior. Row order is a
declared layout assumption, not universal physical tracking.

The separate evaluator now matches left/top anchors one-to-one without rank or
suit matching. Full inferred-box centers are inappropriate for exposed overlap
strips. It finds three transient reference switches and the same one missing /
one duplicate exposure; development V2 has none. This geometry remains diagnostic
within upright rows, not independent proof of arbitrary occluded identities.

Player captions require supported enabled-style panel evidence. Disabled but
legible HIT/STAND cannot establish a turn. VP8 may disconnect thin outlines;
a dark panel with accented horizontal and vertical edges still provides bounded
evidence. Captions alone and unknown styles abstain. Tests preserve obscured,
conflicting controls and ambiguous boundaries, and add disabled controls,
compressed overlap/back presence, equal-rank reveal and evaluator matching.

## Separate measures and development result

R1 requires current player ranks/upcard, correct player phase, legal basic action
and completion within the predeclared **1500 ms** offline budget; it does not
require the hole object's presence. Opportunities are unique round/player-hand
states, not repeated observations. Onset is scored from the full source timeline.
Full-table opportunities additionally require correct visible rank/presence/back
state. This is a Blackjack rank/presence metric, **not complete 52-card reading**:
suits can remain unknown. R2 measures exposures, ID switches, per-rank inventory,
provisional state and confirmation delays separately. Evaluator truth never enters
the observer.

## Capability decision and actual application boundary

Rank-only R1 is usable for offline study in the tested original synthetic upright
rows, blue patterned backs and enabled-panel family, with initial dealer/player/
control calibration. Tested rules are eight decks, one player hand, hit/stand,
no double/split/surrender. Other rule sets, sites, hidden cards and graphics are
not approved by this experiment. R2 stays conditional; final totals do not erase
identity failures. The graphic-transfer gate fails.

Installed desktop 1.1.1 and the default API reader were not replaced. No endpoint
exposes `overlap_challenger`; this is a Python research opt-in. An app research
trial still needs explicit profile/version selection, reviewed ROI previews,
the same authoritative observer feeding the existing advisor, and **real**
screen-sharing checks for cadence, minimized capture, source changes, stale
result expiry and monitor/DPI behavior. HTTP/replays cannot substitute for native
checks. A release needs its own build and validation, not a new framework.

Poker Phase 0 and the advisor are preserved. Rotation/fading/crop/cover keep their
historical results. No model, extra engine batch, training, API inference,
native build, release replacement or merge occurred. This gate is complete;
strategic Poker research need not wait for universal vision.
